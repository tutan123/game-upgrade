# 03 · 逆向方法论（从"泄漏开发版"到源码）

> 这个 DEMO 之所以能拿到近乎源码级的东西，根本原因是**构建时忘了做发布清理**，把 IL2CPP 全量 C++ 输出 + .NET 程序集 + 调试符号全带出来了。这是一次"意外白给"，但它也完整展示了一条**标准 Unity 游戏逆向链路**。

## 3.1 三种源码形态的可读性

| 形态 | 位置 | 可读性 | 怎么读 |
|------|------|--------|--------|
| **.NET 程序集**(Mono DLL) | `_BackUpThisFolder_/Managed/*.dll` | ⭐⭐⭐⭐⭐ | ILSpy / dnSpy 反编译，**几乎等于原 C#** |
| **IL2CPP C++ 输出** | `_BackUpThisFolder_/il2cppOutput/*.cpp` | ⭐⭐⭐⭐ | 变量/方法/类名保留，但被展开成巨大函数 |
| **IL2CPP 元数据** | `il2cpp_data/Metadata/global-metadata.dat` | ⭐⭐⭐⭐⭐ | 字符串/方法签名所在，是"字典" |

**关键**：`.dll` 反编译（ILSpy）是**最优路径**——`Assembly-CSharp.dll` 反编译后基本是原始 C#（命名空间、类名、方法名、局部变量、`switch` 表达式、`yield` 协程都能还原）。`.cpp` 是编译产物，可读但冗长。

## 3.2 那些"长串乱码变量名"是什么

IL2CPP 生成的 `.cpp` 里，名字是 `原名_t<32位哈希>` 两段拼接：
```
ABMrg_tC779BA4EAF445822AB1B6B2F4E9CC986059C4AB5
└─原名─┘ 分隔  └── IL2CPP 唯一性哈希 ──┘
```
- **前缀 = 原始名**（`ABMrg`、`Tool_GetVideoPath`...）。
- **后缀** = IL2CPP 为区分重载/泛型/同名命名空间追加的哈希，无"反解"价值。
- 而且每个函数的上一行注释本来就带着干净签名：
  ```
  // System.String FrameWork.Tool::GetVideoPath(System.String)
  IL2CPP_METHOD_ATTR String_t* Tool_GetVideoPath_m25E4...(String_t* ___0_videoName, ...)
  ```

## 3.3 Il2CppDumper —— 把名字全部还原（我已跑出）

用 `GameAssembly.dll` + `global-metadata.dat`：

```powershell
Il2CppDumper.exe <GameAssembly.dll> <global-metadata.dat> <输出目录>
```

产物（`il2cpp_dump\`）：
| 文件 | 内容 |
|------|------|
| `dump.cs`(15MB) | **全部类/字段/方法的干净名字 + 内存地址(RVA/Offset)**，可直接给 dnSpy/Ghidra 用 |
| `stringliteral.json`(872KB) | **全部 10,347 条字符串**，含所有中文对白/文案（保存存档、加载场景、小游戏结束...）|
| `il2cpp.h`(25MB) | 全部结构体/类定义的 C++ 头 |
| `script.json`(42MB) | 方法地址表 |
| `DummyDll/` | 虚拟 .NET 程序集（供其它工具引用类型）|

验证：`dump.cs` 里能看到 `public static string GetVideoPath(string videoName)` —— 原始名字完整还原。`stringliteral.json` 里有海量中文文本，**等于把游戏全部文案抽出来了**（做剧情研究神器）。

> 注意：`GameAssembly.dll` 是 IL2CPP 的 PE 二进制，`global-metadata.dat` 是其元数据；两者版本必须匹配（这里是 Metadata v31 / Il2Cpp v31）。

## 3.4 资源解包：UnityPy

要解 bundle 里的贴图/图片/预制体/MonoBehaviour，用 **UnityPy**：
- `Texture2D`/`Sprite` 直接 `obj.read().image.save(...)`（内置类型，无需 typetree）。
- **MonoBehaviour 别直接 `read()`**——IL2CPP 打包的 bundle 常无 typetree，`obj.read()` 会段错误。只读 `Texture2D/Sprite` 等内置类型最稳。
- 我在 531 个 bundle 上解出 ~8969 张图。

## 3.5 工具链清单

| 工具 | 用途 | 获取 |
|------|------|------|
| ILSpy / `ilspycmd` | 反编译 .dll → C# | NuGet / GitHub（我用了 8.2 版，需 .NET 6 运行时 + ROLL_FORWARD）|
| Il2CppDumper | dump.cs + stringliteral.json | github.com/Perfare/Il2CppDumper |
| UnityPy（Python）| 解 bundle 贴图/资源 | `pip install UnityPy` |
| dotnet SDK 8 | 跑工具 | dotnet-install.ps1 本地安装 |

## 3.6 一次完整的逆向流程（本例实战）

1. **发现**：`_BackUpThisFolder_ButDontShipItWithYourGame/` + `_BurstDebugInformation_` 在包内 → 漏清理。
2. **代码**：`Managed/Assembly-CSharp.dll` → ILSpy `-p` 反编译 → `Decompiled_CSharp/Assembly-CSharp/*.cs`（412 类）。
3. **元数据**：Il2CppDumper → `dump.cs`（干净名+地址）+ `stringliteral.json`（全部文案）。
4. **资源**：UnityPy 解 bundle → ~8969 图；魔数识别还原媒体 → 997 mp4 + 710 mp3。
5. **综合**：把代码 + 资源 + 元数据交叉印证，得到完整架构。
