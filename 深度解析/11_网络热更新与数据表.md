# 11 · 网络、热更新与数据表

## 11.1 网络（Request / RequestTool）

都基于 `UnityWebRequest` + LitJson，`Content-Type: application/json`，方法 `Methods.Get/Post`（枚举只有 Get/Post）。

- `Request(url, method)` / `Request.Create(int) -> Send()`：`Send()` 起协程 `RequestHttp()`；`Send(Action<string>,err)`、`Send(Action<byte[]>,err)`、`Send(Action<Sprite>,err)`；`Progress:Action<float,int>`（下载进度、Content-Length 字节数）。
- `RequestHttp()` 流程：`new UnityWebRequest(url, method)` + `SetRequestHeader(Content-Type)` + `UploadHandlerRaw(UTF8.GetBytes(JsonMapper.ToJson(_data)))` + `SendWebRequest()`；查 `isHttpError/isNetworkError`→`err`;取 `Content-Length` 作总大小;循环 `Progress`;完成后 `_valueString/_valueByte` 回调。
- **Task 异步封装**：`SendTaskBytes/String/Texture` 用 `TaskCompletionSource<T>` 把回调转成 `await` 风格，再塞进 `StartCoroutine`。
- `Send(Sprite)`：`UnityWebRequestTexture.GetTexture(url)` → `Sprite.Create(texture,...)`。
- `RequestTool` 用 `AddField(object key,object value)` 收集 `Dictionary<object,object>`，发送时整体 `JsonMapper.ToJson(_dic)`；纹理带 `SpriteMeshType.FullRect`。

**区别**：`Request` 面向"单个对象体"，`RequestTool` 面向"表单字段字典"。二者都通过 `SingletonAsMono<Mono>.StartCoroutine` 在全局 Mono 上跑，不依赖具体场景。

## 11.2 下载（DownLoad / DownLoadAbPack）

- `DownLoad.DownLoadAsset(path, progress, data, err)`(:13)：`RequestTool.Create(path, Methods.Get)` GET 字节，`progress` 计算下载速度与文件大小；`data(bytes, filename)` 成功；`err` 失败。`GetPackSize`(:130) 用 `HttpWebRequest.HEAD` 拿 `Content-Length`。
- `DownLoadAbPack`（静态）：`ConcurrentQueue<AbPackDate> _abPackDates`。`AddPackDownTack(list,progress,end,err)`：先累加所有包 `Size` 入队，再递归 `DownLoadAsset`；每包 `Config.DownLoadUrl + Config.GetAbPath() + name`，用 `CurDownLoadSize = Size*progress` 逐包累加总进度；下载完字节存 `PackData`；队列空则 `end()`。

## 11.3 版本检测与热更流程（VersionDetection）

- 清单格式：远端 `Config.DownLoadUrl + abConfigPath + Config.ConfigName`（默认 `ABConfig.txt`），按 `|` 分条目、每条按空格切 `[name, size, md5]`。
- `Detection(abConfigPath, versionInfo, err)`(:12)：下载清单→解析出 `md5 列表`/`name 列表`。对比三个来源：
  1. `streamingAssetsPath`（打包内置初始清单）
  2. `persistentDataPath`（上次热更后的本地清单）
  3. 远端新清单
  - 凡远端 md5 既不在 streaming 也不在 persistent 清单的包 → 加入需下载/更新的 `AbPackDate` 列表；本地 persistent 里有远端已不存在的包 → `File.Delete` 删除旧资源。
- 实际"下载包+写盘+组装 AB"由调用方（HotUpdate 程序集）完成，`Assembly-CSharp` 只负责"算出 diff 列表"。
- **资源定位**：`Config.GetAbPath()` 按平台返回 `/StandaloneWindows64/`、`/Android/`、`/Ios/`、`/WebGl/` + versions + `/`。

## 11.4 HybridCLR 配合（Config / ConfigData）

- `Config`(Config.cs:30-58)：`DataPath=Application.dataPath.Replace("Assets","")`；`DllPath = DataPath+"\\HybridCLRData\\HotUpdateDlls\\"`（编辑器产物）；`DllCopyPath = ...\\Assets\\FrameWork\\Asset\\Dll\\`（拷进 AB 供运行时加载）；`_configData = Resources.Load<ConfigData>(...)`。
- 暴露：`Dlls => _configData.dlls`、`IsAb`、`DownLoadUrl`、`ServerIp/ServerPort`、`Key`。
- `ConfigData`(ConfigData.cs:5-35)：`versions="1.0.0"`、`isAb=true`、`configName="ABConfig.txt"`、`key`、**`dlls=new[]{"HotUpdate.dll"}`**、`downLoadUrl="http://127.0.0.1:3000"`、`serverIp="127.0.0.1"`、`serverPort=8888`。
- 说明：`Assembly-CSharp`（AOT 框架侧）**没有**直接出现 `Assembly.Load/RuntimeApi.LoadMetadataForAOTAssembly` 等 HybridCLR 运行时调用——这些在 `HotUpdate.dll`（未反编译）。这里是**配置与目录约定**：编辑器把热更 DLL 输出到 `HybridCLRData\HotUpdateDlls`，再拷贝到 `Assets\FrameWork\Asset\Dll` 打进 AB，运行时从 AB 取 `HotUpdate.dll` 用 HybridCLR 加载。

## 11.5 数据表（Xlsx / Excel→C#）

### 每表生成"四件套"
- `Xlsx_<Name>.cs`：数据类（字段与列一一对应，含全参+无参构造）。
- `Xlsx_<Name>_Key.cs`：行 key 枚举（强类型引用）。
- `Xlsx_<Name>_Query.cs`：静态加载器 + 查询入口。
- `Xlsx_<Name>_Type.cs`：列名顺序枚举（反映 Excel 表头列序）。

### 加载方式（Xlsx_Event_Query.cs:16-37）
首次访问 `XlsxDataAsOneKey` 惰性触发：
```csharp
string[] array = ABMrg.Load<TextAsset>("Xlsx_Event").text.Split('\n'); // 从 Addressables 加载
string[] array2 = array[2].Split('|');   // 第2行=字段名(列名)
string[] array3 = array[1].Split('|');   // 第1行=字段类型
for (i=3; i<array.Length; i++)
    if (!empty(array[i]))
        type.GetField(array2[j]).SetValue(obj, Tool.ConversionType(array3[j], row[j]));
XlsxDataAsOneKey = new XlsxData<string, Xlsx_Event>("Key", data);
```
- **加载介质**：CSV/TSV 式文本（`|` 分隔）作为 `TextAsset`，通过 `ABMrg.Load<TextAsset>`（Addressables）加载 → **表格也走热更 AB 资源**，可被 `VersionDetection` 增量更新。
- **反射填充**：`Tool.ConversionType(type, value)`(Tool.cs:75) 支持 `int/string/float/long/double/Vector3/Vector2/string[]/int[]/long[]/float[]`，数组按 `,` 切，InvariantCulture。

### 查询结构（XlsxData.cs）
- `XlsxData<T,TV>`(单key)：`Dictionary<T,List<TV>>`，`ByKeyGetValue` 取首条 / `ByKeyGetValues` 取全部。
- `XlsxData<T,TK,TV>`(双key)：`Dictionary<T,Dictionary<TK,TV>>`。
- 每个 Query 默认提供 `XlsxDataAsOneKey`（用列 `"Key"` 建）与 `XlsxDataAsTowKey`（多数空闲）。

### 代表性表
- **`Xlsx_Event`**：`Key/Type/int[] Round/int[] IsNotRound/IsMorning/Count/AutoSave/NotAutoSave/RoleIcon/IsInfinitize/IsNotShowMap/IsShowRound/IsDemo/ShowText/VideoAsset/Desc`。`VideoAsset` 指向 xnode `VideoGraph`。
- **`Xlsx_Item`**：装备/物品，`AddType:string[]` + `AddValue:int[]`（装备提供的属性→数值，被 `GameDataMrg.GetEquipAdd()` 累加）、`AddItemKeys/AddItemValue`(合成配方)、`GetMaxCount/Price/ItemType/ZjType/YfMode/MoveSpeed/Range/IsInfinite`。注意有一个 `public new int GetType` 字段**遮蔽了 `System.Object.GetType()`**，列名须与之一致。
- **`Xlsx_Role`**：极简角色表 `Key/ZhiYe/ChuSheng/SanWei/JianPin`。
- **`Xlsx_MiNiGameLevel`**：`Key/Title/Icon/Target/LoseReward[]/PassReward[]/FistReward[]/FistRewardCount[long]/Time/Scene/Level/IsHasBqb/Desc`。
- **`Xlsx_Language`**：`Key/Chinese/English`，供 `LanguageMrg` 本地化。

## 11.6 值得学习的设计

1. **表格惰性静态加载 + 反射填充**：谁第一次查谁才加载，表格作为 TextAsset 走 Addressables（可热更），反射 + `ConversionType` 转强类型。**表驱动 + 热更**是此类 IP 游戏的核心生产力。
2. **内容寻址 AB + 资源名混淆**：`Tool.GetMd5AsString/GetAbName` 用 MD5 短哈希把 asset 名映射为安全/去重名，`ConvertToEncryptedPath` 混淆视频/音频路径，支持 DLC 高清(High/Nor)。
3. **对象池复用**：`ObjectPool<T>`、`AudioMrg`、`FolderDataMrg`、`Timer/TimerCoroutine`(TimeData 池)。
4. **帧驱动 + 延时统一入口**：`UpdateMrg.OnUpdate`(UnityEvent) + `Timer`/`TimerCoroutine`。
5. **SdkMrg Steam 三层阶梯**：`SteamManager.Initialized` → `IsOpen("HighMode")` → `BIsDlcInstalled`，决定用普通/高清视频资源。
