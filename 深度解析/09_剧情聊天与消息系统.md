# 09 · 剧情聊天与消息系统

聊天（短信/微信式）和邮件是**支线叙事载体**，挂在主线剧情节点（`VideoNode`）**结束之后**被触发，而不是独立并行。

## 9.1 数据模型

- **`ChatGraph : NodeGraph`**：一段聊天脚本（图），继承 XNode，可被 `CreateAssetMenu` 创建。资产名(assetName)是存档里引用它的字符串。
- **`ChatNode`**（核心，ChatNode.cs:12-64）：一个气泡（节点）。
  - `uniqueID`：稳定全局 ID（`Init()`→`UpdateIDInGraph()` 生成 GUID，重复/为空则重新生成），**用于持久化"选过哪个分支"**。
  - `mType`（Text/Image/Video）、`isSelfMsg`（左/右气泡）、`msg`(语言 key)、`img`、`videoClipPath`、`audioPath`。
  - `isHasBtn` + `selectBtnNode`（分支）、`fistPropertyDatas`（选择门槛）、`propertyDatas`（选中后加属性）、`delay`（气泡延迟）、`isEnd`、`taskData`。
- **`StartChat`**（入口）：`[Output] outPut` 连第一个 ChatNode；`maxRound=-1`（可触发的最大回合）。
- **`ChatData`**（VideoNode 上的触发钩子）：`targetId`(发给谁)、`chatNode`(触发的脚本)、`isAlwaysEx`(每次都触发)。
- **`MessageNode/MessageGroup`**：按回合/条件批量推送一段消息（`minRound/maxRound/properties.IsSuc()`）。
- **`MType`**：Text/Image/Video。
- **`MessageData`**：存档里的"一条已发生的聊天块"（`assetName` + `msgType:UnRead/Read`）。
- **`Xlsx_Message`**：会话对象配置（`Key/Type(0短信,1邮件)/Name/Icon/PropertyName/PropertyMaxValue`）。

> **双身份设计**：同一个 `ChatGraph` 资产既是配置（开发期节点图）又是运行时存档的引用（存档只记 `assetName` 字符串，播放时才 `ABMrg.Load<ChatGraph>(assetName)` 重新载入）。**存档小而稳定、改表不用重开档。**

## 9.3 与主线 VideoNode 的关系

- `VideoNode.cs:161` 持有 `List<ChatData> chatData`。
- 视频播完 → `AddChat`。聊天里做的属性/任务/选择反过来影响后续章节，形成剧情闭环。

## 9.4 心跳/好感系统（FMV 心动故事收藏画廊）

- 入口 `RecordWindows.XinDon` → `OpenUi<HeartbeatWindows>`。
- `HeartbeatTool`：播放两个交替循环的背景视频（`oneVideo/twoVideo`），`PlayVideo` 先淡出再切换；`CheckShowUnLock` 根据 `IsCanShow` 切解锁座显示——但 **`IsCanShow` 在反编译里是桩函数（恒 true）**，真实门槛未保留。
- `HeartbeatItem`：随机起播 + 监听 `ChangeHeartbeat` 切动画；`OnClick` 按 `heartbeatType` 打开对应该角色的 `VideoListWindows`。
- **"心动值"本质 = 角色好感属性**：`PropertyTypeValue` 里各角色 `*Favorability`（BZP/WDLY/XFP/XXG/LQT/MM/LBN/ZXSN/DBN/LJ/XJM/NAM/MS/PZ/TSGSN/XXSN/WY/LXY）+ `XinDonLiShangXian`(上限) + `XinDonLiHuiFu`(恢复)。
- 聊天窗口顶部好感条 = `GetProperty(xlsxMessage.PropertyName,"Property",0) / PropertyMaxValue` 的百分比。

## 9.5 存储：聊天记录如何进存档（GameDataMrg）

- `AddChat`(行 819-836)：`Chat_<key>`(List<string> 仅记录已触发脚本名，去重) + `Chat_Data<key>`(List<MessageData> 真正展示的消息条)。
  - **去重**：`isAlwaysEx=false` 时同一 `assetName` 只入档一次（剧情短信不重复）；`isAlwaysEx=true` 每次都追加（可重复日常）。
  - 追加默认 `UnRead` 并亮红点 `SetShowChatRed(key,true)`。
- `SetChatNewTime/GetChatNewTime`：`Chat_Time<key>` 毫秒时间戳，列表排序。
- `GetChat`：反序列化 `Chat_Data<key>`。
- `SetRead`：把指定 `assetName` 的 `msgType` 改 `Read`。
- `SetShowChatRed/IsShowChatRed`：`ChatRed_<key>` 红点；`IsShowPhoneRed`：任一 `Type==0` 会话有红点则手机整体亮红。
- `GetMsgSelectId/SetMsgSelectId`：`Chat_Select`（`Dictionary<string,string>`）记录"节点 uniqueID → 所选分支 uniqueID"。
- `GetChatCount/AddChatCount`：防止一个节点带的任务重复发（`ChatItem.Init` 中 `GetChatCount(uniqueID)<=0` 才 `SetTask`）。

## 9.6 值得学习的设计

1. **"配置 Asset 即存档引用"**：存档只存 `assetName` 字符串，播放时才加载，存档小而稳定、改表热更友好。
2. **节点图驱动分支 + 用 uniqueID 做分支记忆**：`Chat_Select` 字典把"玩家选过的分支"持久化，回放时据此重走分支。
3. **触发与展示解耦**：`AddChat` 只在剧情后置/回合条件处写一条 `MessageData`；`PhoneWindows/EmailWindows` 只从存档读并递归还原。
4. **用 `delay` + 短信音效模拟真实打字/查看节奏**（`async/await Task.Delay` 逐个吐气泡）。
5. **红点/已读/排序统一由存档布尔与时间戳驱动**，UI 监听 `UpdateChatRed` 事件刷新。
6. **属性条件与增益都用同一套 `PropertyData`**，聊天分支既能"门槛"又能"奖励"。
