## 1.3 脚本模式：IL2CPP + HybridCLR（关键）

这不是纯 IL2CPP 静态游戏，而是**混合热更**：

- **AOT 主程序集**：`Assembly-CSharp.dll`（框架/导演侧，684KB，**我们已完整反编译**）。
- **C# 热更**：HybridCLR，运行时加载 `HotUpdate.dll`（玩法主体）。
  ```csharp
  // FrameWork/Config.cs
  DataPath    = Application.dataPath.Replace("Assets","");
  DllPath     = DataPath + "\\HybridCLRData\\HotUpdateDlls\\";   // 编辑器产物
  DllCopyPath = DataPath + "\\Assets\\FrameWork\\Asset\\Dll\\";   // 拷进 AB 供运行时加载
  ```
  ```csharp
  // FrameWork/ConfigData.cs (ScriptableObject)
  public string[] dlls = new[]{ "HotUpdate.dll" };                // ★ 要热更的程序集
  public string downLoadUrl = "http://127.0.0.1:3000";            // 热更/下载服务器(本地)
  public string serverIp = "127.0.0.1";  public int serverPort = 8888;
  ```

> **重要结论**：我们反编译看到的 `Assembly-CSharp` 是"导演/框架"部分；真正的**玩法逻辑在 `HotUpdate.dll`**（未随 Demo 分发或已并入 `Assembly-CSharp`）。所以框架层、剧情编排、UI、资源、数值**全部可见**，但部分高级玩法细节可能在热更 DLL 里。这属于"能看懂架构但非 100% 玩法齐全"的典型情况。

## 1.4 关键取舍（为什么这样配）

- **IL2CPP**：提升性能 + 一定程度反逆向（这次没生效，因为构建漏删）。
- **HybridCLR**：买量手游刚需——**不重新上架就能修 bug / 上活动 / 改数值**。AB 包 + DLL 一起热更。
- **Addressables**：把 28 GB 视频和 1.2 GB 资源切成 531 个 bundle，按需加载 / 增量热更 / 分包。
- **CEF 内嵌浏览器**：用 HTML5 做轻玩法/活动，前端可以独立开发，不动客户端。
