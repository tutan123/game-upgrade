## 1. 这到底是个什么游戏

把代码读完后，它的"玩法配方"非常清晰——**一条 FMV 主线 + 一堆挂在视频上的玩法钩子**：

- **主线是视频**：剧情 = 一张张 `VideoGraph`（节点图），每个节点 `VideoNode` 播一段视频 CG。
- **视频上挂交互**：播放中按时间点（`evenTime`）触发事件——弹选择按钮、开 QTE、开战斗、开酒桌、开商店、切昼夜、自动存档。
- **视频外挂玩法**：玩到某节点跳进小游戏（抓娃娃/钓鱼）、战斗、喝酒、抽卡、宝可梦式收集、HTML 弹珠台。
- **养成是数值网**：4 维基础属性 + **18 个女主好感度** + 酒量 + 执行力 + 金钱 + 压力 + KPI，全部由节点/小游戏/选择加减。

一句话：**"视频是骨架，玩法是挂件，数值是胶水"**。这是典型的国内剧本类互动叙事手游架构，非常值得学习其"内容驱动"的工程组织方式。

## 2. 技术底座（为什么这么选）

| 技术 | 角色 | 为什么选它（设计动机） |
|------|------|----------------------|
| **Unity 2021.3 LTS** | 引擎 | LTS 稳定版，2021 是国产手游主流基线 |
| **IL2CPP** | 脚本后端 | AOT 提升性能 + 提高逆向门槛（虽然这次没用）|
| **HybridCLR** | C# 热更 | ★ 不重新上架就能修 bug/上活动/改数值，是买量手游的刚需 |
| **Addressables** | 资源系统 | 按需加载/热更/分包，把 28GB 视频和 1.2GB 资源解耦 |
| **AVProVideo** | 视频 | Unity 自带 VideoPlayer 不够：要精确 seek、预加载下一段、切换分辨率(Nor/High)、360° |
| **ZFBrowser(CEF)** | 内嵌浏览器 | 用 HTML5 做轻玩法/活动页，前端同学可独立开发，不用动客户端 |
| **XNode** | 节点图 | 把"剧情分支"做成策划能拖的可视化图，程序不用写死流程 |
| **DOTween** | 补间 | UI/血条/按钮动效 |
| **Odin + Sirenix** | 编辑器 | 让 Inspector 里配数据很舒服（策划/程序体验）|
| **LitJson** | JSON | 存档/配置序列化 |
| **ExcelDataReader** | 读 Excel | 策划用 Excel 配表，工具链转 C# |
| **Steamworks.NET** | Steam | 成就/DRM/云存档 |
| **PolyPerfect** | NPC 包 | 3D 地图里的路人 AI/行走/音效（买的现成资产）|
| **Audio360** | 空间音频 | 360° 视频的环绕声 |

**学到的取舍**：这套选型全是"**买量手游的标准答案**"——热更(HybridCLR)、分包(Addressables)、视频(AVPro)、内嵌H5(CEF)、可视化配表(XNode+Excel)。如果你要做类似品类，这套组合几乎是免思考的起点。

## 4. 自研框架 FrameWork（最值得学的部分）

`Assembly-CSharp.dll` 里 `FrameWork` 命名空间是一套**完整的小型游戏框架**。读它=读一本"国内商业手游框架教科书"。

### 4.1 启动入口
```csharp
// FrameWork/Main.cs —— Unity 启动即执行，无需挂在场景上
[RuntimeInitializeOnLoadMethod]
public static void Run() {
    DOTween.defaultAutoKill = true;
    LoadMrg.LoadAsNotyMapLoad(Scenes.Load);   // 进 Load 场景
}
```

### 4.2 事件总线（EventManager）
两级字典 + 委托多播 + **对象池复用消息参数**（避免 GC）：
```csharp
ConcurrentDictionary<int/*MessageType*/, ConcurrentDictionary<int/*具体事件*/, Action<List<object>>>>
// 用法
EventManager.AddListener(MessageType.Video, VideoMessageType.OpenBox, OpenBox);
EventManager.DispatchEvent(MessageType.Game, GameMessageType.UpdateProperty, msg);
```
消息分四类：`Game / Ui / Net / Video`（各自一个枚举：`GameMessageType`、`UiMessageType`、`NetMessageType`、`VideoMessageType`）。

### 4.3 UI 框架（MVC 变体）
- 每个界面 = 一个 `XxxWindows : UiActor : Actor`。
- 生命周期：`Awake/Start/Open/CloseUi/OnClose/OnEnable/OnDisable/Update`。
- 开/关自动 DOTween 动效（Bg 淡入、View 0.6→1 缩放）。
- **打开 UI 会自动暂停剧情视频，关闭自动恢复**（`PauseEsc/PlayEsc`）——这是 FMV 游戏很贴心的细节。
- 用特性声明窗口元数据：`[UiMode(Mode.Background, true)]`、`[ActorInfo("", "CombatWindows")]`。
- 界面多达 **70+ 个**（LoadWindows/MainWindows/CombatWindows/ShopWindows/MapWindows/WineListWindows/EmailWindows/PhoneWindows...）。

### 4.4 资源封装（ABMrg）
对 Addressables 的薄封装，统一收口 Load/Release：
```csharp
ABMrg.Load<GameObject>("BiaoQinBao");          // 同步
ABMrg.LoadAsync<VideoGraph>(name, cb);          // 异步
ABMrg.ReleaseAllAssets();                        // 释放 + UnloadUnusedAssets + GC
```

### 4.5 其它标配
- **单例**：`SingletonAsClass<T>` / `SingletonAsMono<T>`（管理器遍地都是）。
- **对象池**：`ObjectPool` / `ObjectPoolAsComponent` / `ObjectPoolAsGameObject`。
- **网络**：`Request`/`RequestTool`（指向 `127.0.0.1:8888` 的本地服务器，Demo 没真正联网）。
- **热更/下载**：`DownLoad`/`DownLoadAbPack`/`VersionDetection`（配合 HybridCLR）。
- **实体/动画**：`Actor`/`EntityManager`/`AnimationController`。

> 命名习惯很有意思：`Mrg`=Manager、`Windows`=界面、`AsXxx`=按某种方式。这套"土命名"在国内中小团队极常见，读它能快速适应真实项目。

## 5. 核心引擎：FMV 互动叙事系统

这是全游戏的心脏。理解它就看懂了这游戏。

### 5.1 内容即图（XNode）
- `VideoGraph : NodeGraph` = **一个剧情事件**（对应 `xlsxEventKey`）。
- 图里的节点：`VideoNode`（视频）、`ButtonNode`（选择按钮）、`ChapterNode`（章节）、`MessageNode`（消息）、`AchievementNode`（成就）、`IsHasVideo`/`VideoIf`（条件）等。
- 节点间用 XNode 的 `[Input]/[Output]` 端口连线 → **策划拖图即写剧情，程序零改动**。

### 5.2 VideoNode：一个视频节点能装多少东西
`VideoNode`（199 行字段）是信息密度最高的类，一个节点包含：

| 类别 | 字段（摘选） | 作用 |
|------|------------|------|
| 视频 | `videoPath/videName`、中英字幕 `subtitleChinese/English` | 放哪段、配什么字幕 |
| 循环 | `isLoopVideo/isToNextVideoToLoopStart` | 待机循环片段 |
| 分支出口 | `nextVideoNode`、`qteFail`、`playDieVideoNode`、`enemyDieVideoNode` | 多结局连线 |
| 按钮 | `isHasBtn`、`videoBtnShowTime/HideTime` | 定时浮现的选择按钮 |
| QTE | `isHasQte`、`qteDatas`（QteData 列表）| 内嵌 QTE |
| 战斗 | `isInitHp`、`enemyHp`、`bossName` | 这一段是战斗 |
| 酒桌 | `isHasWineList`、`isInitJiuLian/targetJiuLian` | 这一段开酒局 |
| 360° | `is360Video/maxY/minY/img360` | 全景视频 |
| 副作用 | `PropertyData/setPropertyData/achievement/taskData/chatData/EventValue/VideoEndEventValue` | 加属性/解锁成就/发消息/触发任务 |
| 转场 | `isToMap/isToGame/isToNextGroup/isPlayerEndOver` | 去地图/小游戏/下一事件/结束 |

### 5.3 运行时：GameScene + VideoItem
- **`GameScene.PlayVideo(node)`** 是主循环：
  1. 存档当前进度（`CurEventKey/CurVideoId`）
  2. 360° → 切 `Video360Scene`
  3. **预加载**后续片段（`loadRect1` 当前、`loadRect3` 预加载队列），切换无缝
  4. 切换时 `rawImage.texture = videoItem.CopyRtToTex()` 定格上一帧做过渡，再 `FadeVideo()` 淡入
  5. 解析 SRT 字幕
  6. `videoItem.Play()`
- **`VideoItem.Update()`** 每帧检查：
  - 到 `evenTime` → 触发 `EventValue` 里的 `VideoMessageType` 事件（开战斗/酒局/商店…）
  - 到 QTE 时间 → `CheckQte()` 生成 QTE 控件
  - 到属性时间 → `AddProperty` 加属性
- **视频结束 `VideoEndAddAndToOther(node)`**：结算属性/成就/聊天/任务/事件 → 按出口走下一节点（随机/顺序/固定/按 QTE 成败）。

### 5.4 玩家控制
- `空格` 暂停/播放（战斗/QTE 中禁用）
- `Q` 跳过（**仅当该视频已解锁/看过**，`IsUnLockGlobalKey`）→ 有按钮则快进到按钮时刻，否则快进到结尾
- 倍速 2x（同样要求已解锁）

### 5.5 彩蛋
`OpenBox` 事件弹输入框，输入密码（默认 `798`）解锁隐藏视频（`isSucVideo`）——典型的"隐藏福利"设计。

## 6. 分支与交互：选择 / QTE / 条件节点

### 6.1 选择按钮（ButtonNode）
视频的 `[Input]` 可挂 `ButtonNode`，播放到 `videoBtnShowTime` 浮现：
- `btnName`（多语言文本）、位置、大小、图标
- **消耗/门槛**：`usePropertyDatas`（且）/ `usePropertyDatasOr`（或），不够则弹提示
- **点击效果**：`propertyDatas`（改属性）、`eventDatas`（发事件）、`isOpenUiBtn`+`uiName`（开界面）、`isJoinCombat`（进战斗）、`isCheckVideoExists`（解锁视频）
- 每个按钮的 `[Output]` 连到不同 `VideoNode` → **选项决定剧情走向**

### 6.2 QTE（QteType）
```
NoneGo / CondensationGo(长按蓄力) / KeyGo(按键) / SlideGo(滑动) / ClickGo(连点) / NoneFailGo
```
- `QteData`：`qteStartTime/EndTime`（出现窗口）、`clickCount`（需点几次）、`qteLoc`（位置）、成败各挂 `sucPropertyData/losePropertyData`。
- 到点 `Instantiate(ABMrg.Load(qteType.ToString()))` 生成对应控件 → `QteBtn`。
- 成败计入 `QteSucCount/QteFailCount`，视频播完按**是否全部成功**走 `qte成功/失败` 分支。

### 6.3 条件节点（VideoIf / IsHasVideo / VideoIfAsType）
- `VideoIf`/`VideoIfAsType`：按属性/条件分流（如"如果拥有某视频/某属性则走A否则走B"）。
- `VideoIfPlayerEbriety/VideoIfTargetEbriety`：**按"醉酒度"分流**——和酒桌系统联动。

## 7. 战斗系统：视频驱动的"回合制功夫"

战斗（`CombatWindows`，641 行）非常取巧——**用放视频代替做打斗动画**：

- 打开战斗窗口，双方血条（`PlayerHp/TmpPlayerHp`、`EnemyHp/EnemyHpMax`），DOTween 血条动画 + 飘字伤害。
- 技能按钮每个对应一个 `VideoNode`（放对应打斗片段）：

| 按钮 key | 技能 | 备注 |
|----------|------|------|
| `PuTon` | 普通攻击 | 必有 |
| `JinShengGonJi` | 近身攻击 | |
| `ZhuHeQuan` | 组合拳 | 需属性>0 解锁 |
| `JunTiQuan` | 军体拳 | 需解锁 |
| `RuLaiShengZhang` | 如来神掌 | 需解锁（大招）|
| `XiXueGuiHuiXue` | 吸血鬼回血 | 需解锁（吸血）|
| `YonChun` | 咏春 | 需解锁 |

- 技能点 `TmpJiNengDian`：放技能耗点；技能有 `<sprite name=ZJD>`（技能点图标）消耗显示。
- 点技能 → 校验消耗 → `GameScene.PlayVideo(videoNode)` 播放这段打斗视频 → 视频里再通过 `VideoEndPropertyData`/QTE 扣血。
- 分支出口 `enemyDieVideoNode`（打赢）/`playDieVideoNode`（打输）→ 进入不同结局视频。

**学习点**：对 FMV 团队，"战斗=精心剪辑的打斗视频 + 血条数值 + 技能解锁"是极低成本高表现力的方案。

## 8. 酒桌/喝酒系统

逆袭题材的标志性玩法（`WineListWindows`/`HeJiuWindows`/相关事件）：
- 属性：`CapacityForLiquor`（酒量）、醉酒值 `Tmp/TargetJiuLian`、`JiuLianBiLi`（酒量比例）。

## 9. 小游戏矩阵

游戏内置了 **5+ 种小游戏**，全部"挂"在剧情节点上，玩完把结果（奖励/成败）回传给剧情：

### 9.1 抓钩/黄金矿工（Hook.cs + MiNiGameMrg.cs）★ 最完整
经典"黄金矿工"：
- `Hook` 三态：`Rotate`（左右摆）→ 点击 `Shoot`（发射）→ `Retract`（回收，速度=射速/物品重量）。
- 物品 `ItemType`：`Nor`(普通)、`BiaoQinBao`(表情包)、`CaiDanBao`(彩蛋包)、`ZhaDan`(炸弹)、`DianZan`(点赞)。
- **道具加成**（都是持久属性，可在别处养成）：`ShuDu`(速度)、`DaXiao`(大小)、`ErWaiJianLi`(额外奖励)、`FuZhuCao`(辅助瞄准线)、`ZhaDan`(炸弹清屏)、`DaLiYaoShui`(大力药水-炸不怕)。
- `CaiDanBao` 随机给 体力/智慧/魅力/金钱。
- 计分达标 → `GameOver(isSuc)` → 发奖励（首通/通关/失败三种奖励）→ **回传剧情**：按 `videoNode.isToNextGroup/isPlayerEndPlayerNext/isToMap` 决定回哪个场景/下一段视频。

### 9.2 视频反应面板（SiWaMrg.cs）
抓娃娃时的"陪伴演出"：抓到表情包触发 `GetXiaoLian` 事件 → 随机播一段女主反应视频（按关卡分 二阶/六阶/七阶/九阶 不同剪辑）。**用小视频做即时正反馈**。

### 9.3 宝可梦式收集（BaoKeMengWindows + OpenBaoKeMengUi）
事件 `OpenBaoKeMengUi` 触发，疑似"收集/图鉴"玩法。

## 12. 资源管线与混淆（以及我如何还原）

### 混淆机制（`FrameWork/Tool.cs`）
```csharp
GetVideoPath(name) = streamingAssetsPath + "/" + ConvertToEncryptedPath("Video/Nor"+name) + ".PNG"
ConvertToEncryptedPath: 每个路径段 → GetShortIdentity0Gc
GetShortIdentity0Gc(key) = Base62( | (long)MD5(key).前8字节 | )
```
- 结果：`StreamingAssets/i55N8rvfL6a(=hash"Video")/djWu27ED936(=hash"Nor")/<组hash>/<文件hash>.PNG`
- 视频统一改 `.PNG`、音频统一改 `.JPG` → **伪装 + 反爬 + 规避加载白名单**。
- 4K 高清走 `hash("High")="5xuAwMZuBy8"`（Demo 未附）。

### 我的还原（已做）
- 用**文件头魔数**逐个识别：997 个 `.PNG` 全是 **MP4**，710 个 `.JPG` 全是 **MP3**（**没有一张真图片**）。
- 全部复制+改回正确扩展名到 `重生2我独自逆袭Demo_媒体资源/`（视频 27.5GB / 音频 0.59GB），并生成 `_manifest.csv` 对照表。
- 验证了哈希算法（`hash("Video")="i55N8rvfL6a"`），理论上可用"候选名→哈希→比对"反推部分原始命名（MD5 不可逆，只能正向穷举）。

## 13. 存档系统

- 存档 = `Dictionary<string,string>` → LitJson → **AES(Rijndael/CBC)** → `persistentDataPath/data.dat`。
- Key 硬编码在 `Config/Tool`（`kljsdkkdlo4454GG00155sajuklmbkdl`）。
- **断点续玩**：存 `CurEventKey + CurVideoId`，下次直接从当前视频节点继续。
- **已看跳过**：`AddUnLockKey(uniqueID/videoPath)`，看过的视频才能 Skip/倍速。
- 自动存档：`VideoMessageType.AutoSaveData` 在关键节点自动存。

## 16. 给学习者：这套架构的精华与坑

### 值得学的设计模式
1. **内容即图（XNode）**：把分支剧情做成可视化图，策划自助，程序零改。这是叙事游戏生产力关键。
2. **事件驱动 + 对象池消息**：`EventManager` 解耦模块，`List<object>` 消息体对象池复用，注意 GC 意识。
3. **FMV 玩法钩子**：`evenTime` 时间轴事件 = 在视频上"打点"触发玩法，极低耦合地把玩法缝进 CG。
4. **预加载无缝切换**：`loadRect1/3` 双队列 + `CopyRtToTex` 定格过渡 + `FadeVideo` 淡入，解决视频切换黑屏。
5. **热更三件套**：HybridCLR（代码）+ Addressables（资源）+ 本地服务器配置（`ConfigData`），上线后能持续运营。
6. **数据分层**：Excel 配数值 / XNode 配流程 / ScriptableObject 配全局，职责清晰。
7. **原生+H5 双小游戏**：轻重分离。

### 要避开的坑（它自己踩过的）
1. **千万别忘删 `_BackUpThisFolder` / `_BurstDebugInformation`** —— 否则源码全暴露（本项目就是活教材）。
2. **加密 Key 不要硬编码在代码里**（本项目存档 Key 明文）。
3. **服务器地址不要用 localhost 占位发版**（本项目指向 127.0.0.1）。
4. **资源"改后缀"不是加密** —— 只能挡小白，魔数一识别就破。真要保护得做内容加密 + 自定义加载。
5. **超大文件拼接要写对头**（4.5GB 视频 ftyp size 错误的教训）。
6. `Assembly-CSharp` 单一程序集偏大（684KB/412类），大项目建议拆分 Assembly Definition。

### 你可以拿它练手的事
- 照着 `GameScene + VideoNode` 自己写一个最小 FMV 播放器（XNode 图 + AVPro + 时间轴事件）。
- 复刻 `EventManager` 对象池消息总线。
- 用 Excel→C# 生成器做一套自己的配表管线。
- 把 `Hook.cs` 黄金矿工改造成你自己的小游戏（它已经写得很完整）。
