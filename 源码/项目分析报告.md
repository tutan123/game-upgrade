## 5. C# 热更新：HybridCLR

这是本作**最重要的架构特征**之一（不是纯 IL2CPP 静态编译，而是带 C# 热更的混合模式）：

```csharp
// FrameWork/Config.cs（静态构造函数）
DataPath    = Application.dataPath.Replace("Assets","");
DllPath     = DataPath + "\\HybridCLRData\\HotUpdateDlls\\";   // ← HybridCLR 热更 DLL 目录
DllCopyPath = DataPath + "\\Assets\\FrameWork\\Asset\\Dll\\";
```

```csharp
// FrameWork/ConfigData.cs（ScriptableObject，挂在 Resources）
public string[] dlls  = new[]{ "HotUpdate.dll" };
public string downLoadUrl = "http://127.0.0.1:3000";           // 热更服务器（当前为本地）
public string serverIp   = "127.0.0.1";
public int    serverPort = 8888;
public string key        = "kljsdkkdlo4454GG00155sajuklmbkdl"; // 存档/资源加解密 Key
```

**含义**：
- 主工程是 IL2CPP（`Assembly-CSharp.dll` 中的**框架**），业务逻辑（玩法、活动、剧情、小游戏）以 **HotUpdate.dll** 运行时由 HybridCLR 加载，从而支持**不重新打包就能上线更新**（修 bug、加内容、热改数值）。
- 热更服务器、游戏服都指向 `127.0.0.1`，**印证这是一个本地开发/测试构建**，而不是面向正式服的黑盒版本。
- `downLoadUrl=http://127.0.0.1:3000` 同时服务于 AB 包与 DLL 热更下载。

> 注意：我们拿到的 `Assembly-CSharp.dll` 是含框架 + 部分玩法的一体化程序集；真正的"HotUpdate.dll"在本次 Demo 的 `Managed` 中**未看到**（或被打包进别处/未随包分发），因此玩法层的部分逻辑可能没有直接反编译到，但框架层（`Assembly-CSharp`）已还原得相当完整。

### 6.2 存档系统（反面教材级 "自定义加密"）
```csharp
// FrameWork/Tool.cs —— 二进制加密
public static byte[] Encrypt(byte[] toEncryptArray, string key) =>
    new RijndaelManaged { Key=Convert.FromBase64String(key), Mode=CipherMode.ECB, Padding=PaddingMode.PKCS7 }
        .CreateEncryptor().TransformFinalBlock(...);

// FrameWork/GameData.cs
public static void Save() {
    string s = JsonMapper.ToJson(_dataDic);              // LitJson
    byte[] bytes = Tool.Encrypt(Encoding.UTF8.GetBytes(s), Tool.Key);
    File.WriteAllBytes(Application.persistentDataPath + "/data.dat", bytes);
}
```
- 存档为 **key-value 字典 → JSON → AES 加密** 写入 `data.dat`。
- 另有字符串级 `Encrypt/Decrypt`（AES-CBC，Key/IV = MD5(key)）用于文件名/资源名。

### 6.3 资源路径混淆（解释了 `.PNG` 视频）
```csharp
// FrameWork/Tool.cs
public static string ConvertToEncryptedPath(string originalPath) {
    // 按 '/' 分段，每段调用 GetShortIdentity0Gc(segment)
}
public static string GetShortIdentity0Gc(string key) {
    byte[] b = Encoding.UTF8.GetBytes(key);
    ulong n = (ulong)Math.Abs(BitConverter.ToInt64(_md5.ComputeHash(b),0));  // MD5 前 8 字节 → long
    // 用 base62 编码，最长 11 位
}
public static string GetVideoPath(string videoName) =>
    Application.streamingAssetsPath + "/" + ConvertToEncryptedPath("Video/Nor"+videoName) + ".PNG";
public static string GetFileDecryptName(string fileName, string end=".Png") => Encrypt(fileName) + end;
```
**机制**：把每个路径段 `"Video"`、`"Nor主线名"` 等取 **MD5 → 8 字节 long → Base62（0-9a-zA-Z）** 得到短串，从而把 `Video/Norxxx.mp4` 映射成 `i55N8rvfL6a/djWu27ED936/<hash>/<hash>.PNG`。文件后缀统一改成 `.PNG`/`.JPG`，**目的**：
1. 混淆 / 反盗链：外人很难直接看出资源是什么、如何命名。
2. 规避工具/加载器的白名单（把视频伪装成纹理），并配合 AVProVideo 按字节流播放。

> 这也解释了为什么 `i55N8rvfL6a\djWu27ED936\` 两级的 16 字符 hash 是**全局固定前缀**（对应 `"StreamingAssets"/"Video"` 等段的混淆结果）。

## 7. 数据驱动设计（Excel → C#）

`Xlsx` 命名空间是典型的 **Excel 配置 → C# 类** 自动生成产物，每个配置表生成 4 类文件（`Table` / `Table_Key` / `Table_Query` / `Table_Type`），对应一个**枚举 Key 表**：

| 数据表 | 用途（从表名/代码推断）|
|--------|----------------------|

| `Xlsx_Chapter` | 章节 |

| `Xlsx_Event` | 剧情事件（含自动存档 flag、角色图标）|
| `Xlsx_Item` | 道具 |
| `Xlsx_Language` | 多语言（A1700/A1701/... 键）|
| `Xlsx_Message` | 消息 |
| `Xlsx_MiNiGameItem` / `Xlsx_MiNiGameLevel` | 小游戏道具 / 关卡 |
| `Xlsx_Pos` | 坐标/点位 |
| `Xlsx_Record` | 记录 |
| `Xlsx_Role` | 角色 |
| `Xlsx_RoundInfo` | 回合信息 |
| `Xlsx_Task` | 任务 |
| `Xlsx_WineList` | 酒单 |

**查询方式**（贯穿全工程）：
```csharp
Xlsx_Event_Query.XlsxDataAsOneKey.ByKeyGetValue(xlsxEventKey)

```
这种方式让策划通过改 Excel 就能调整数值/文本，无需改代码。
